# Project Guidelines for Junie (Project-Specific)

This document captures concrete, project-specific practices for development, build, testing, and debugging of excog-trajectory. It is intended for experienced developers working on this repository.

## Project Overview (context)
Analysis of exposomic trajectories of cognitive decline using NHANES data. Core modules implement data loading/cleaning and MICE imputation, PLS-based analyses, visualization, and a CLI entry point.

Repository entry points and tooling:
- Package name: excog-trajectory (import package excog_trajectory)
- CLI entry point: excog (excog_trajectory.cli:main)
- Tests under tests/ with strict marker configuration
- Build system: hatchling

## Environment and Build/Configuration

- Python: pyproject requires >=3.11 (project.requires-python). Note that tool configs (Black/Mypy/Ruff) target py38; see notes below.
- Dependency manager: uv is recommended (README). Alternatively, standard pip works if you prefer.

Recommended setup (development):
- Create a virtual environment for Python 3.11+
- Install package and dev tools with uv (fast and lock-aware):
  - uv pip install -e .
  - uv pip install -e ".[dev]"
- Build (if you need a wheel/sdist):
  - pip install build
  - python -m build

CLI defaults and data/results layout (as of src/excog_trajectory/cli.py):
- excog download defaults:
  - --output-dir data/raw
  - --direct-url ["https://osf.io/download/9aupq/", "https://osf.io/download/9vewm/"]
  - --filename nhanes_data.csv
- excog clean defaults:
  - --output-dir results
  - --output-data data/processed
- excog impute defaults:
  - --data-path data/processed/cleaned_nhanes.csv
  - --output-path None (autogenerated if not provided)
  - --n-imputations 5, --n-iterations 5, --random-state 42
- PLSR/SNF/trajectory subcommands have additional tunables and write under results/; see cli.py for details.

Data module highlights (src/excog_trajectory/data.py):
- download_nhanes_data(direct_url, output_dir, filename) uses urllib; expects write access to output_dir.
- impute_exposure_variables(...) uses miceforest; ensure scikit-learn and numpy versions match pins in pyproject.

## Testing

Pytest configuration (pytest.ini):
- testpaths = tests
- Strict markers enabled: unit, integration, slow, download
- Discovery patterns: python_files = test_*.py, python_classes = Test*, python_functions = test_*

Prerequisites for running the full test suite:
- The tests and fixtures import pandas, numpy, matplotlib, scikit-learn, etc. Install dev extras: uv pip install -e ".[dev]" (and the base package: uv pip install -e .). On some systems you may also need system BLAS/linear algebra libs for numpy/scipy.

Common test invocations:
- Run all unit tests: pytest -m unit
- Exclude slow and download: pytest -m "unit and not slow and not download"
- Verbose with strict markers (default): pytest -v
- Run a specific test file: pytest tests/unit/test_cli.py -q

Adding tests:
- Place new unit tests under tests/unit/ with filenames test_*.py; use the defined markers to avoid strict marker failures.
- If adding tests that need network or heavy data, mark them @pytest.mark.download or @pytest.mark.slow respectively.

Demonstration: minimal smoke test (no heavy deps)
- To quickly validate the repo without importing the package (useful before installing scientific deps), you can use the following test that checks version consistency. We verified it passes locally.

Example file (place outside tests/ to avoid loading tests/conftest.py): .junie/tmp/test_smoke_guidelines.py

```python
import re
import pathlib
import tomllib

ROOT = pathlib.Path(__file__).resolve().parents[2]

def test_version_consistency():
    # Read version from pyproject.toml
    pyproject = ROOT / "pyproject.toml"
    data = tomllib.loads(pyproject.read_text())
    proj_version = data["project"]["version"]

    # Extract __version__ literal from package __init__.py without importing package
    init_py = ROOT / "src" / "excog_trajectory" / "__init__.py"
    m = re.search(r"__version__\s*=\s*\"([^\"]+)\"", init_py.read_text())
    assert m, "__version__ not found in __init__.py"
    pkg_version = m.group(1)

    assert proj_version == pkg_version
```

Run only this smoke test:
- pytest -q .junie/tmp/test_smoke_guidelines.py

After validating, remove the temporary file to keep the repo clean.

## Code Style, Linting, and Types

Configured in pyproject.toml:
- Black: line-length 88, target-version py38
  - Run: black src/ tests/
- isort: profile black, line_length 88
  - Run: isort src/ tests/
- Ruff: E,F,B,I, line-length 88, target-version py38
  - Run: ruff check src/ tests/
- mypy: strict-ish (disallow untyped defs/incomplete defs), python_version = 3.8
  - Run: mypy src/

Note on tool target-version mismatch:
- Runtime requires Python >=3.11, while Black/Ruff/Mypy target py38. This is acceptable but can limit type-checking and syntax usage in CI/tooling. If you modernize code to 3.11+ syntax or stdlib APIs, consider updating tool targets:
  - [tool.black].target-version = ["py311"]
  - [tool.ruff].target-version = "py311"
  - [tool.mypy].python_version = "3.11"
Ensure you coordinate such changes across the repo and CI to avoid spurious failures.

## Practical Dev Notes

- CLI help: excog --help and excog <subcommand> --help reflect current defaults and arguments defined in cli.py.
- Data directories: scripts write under data/raw, data/processed and results/*; ensure these exist or let the CLI create them (it calls os.makedirs with exist_ok=True in clean).
- Reproducibility: many functions accept random_state; pin as needed (default 42 or 1203 in some analysis helpers).
- Pinned versions: numpy==2.3.0, pandas==2.3.0, scikit-learn==1.7.0, scipy==1.15.3; mixing with other versions may break numerical behavior.

## Quickstart: Full local validation

1) Create env and install deps
- uv pip install -e .
- uv pip install -e ".[dev]"

2) Run unit tests only (skipping network/slow):
- pytest -m "unit and not slow and not download"

3) Lint/format/type-check:
- ruff check src/ tests/
- black --check src/ tests/  # or black src/ tests/
- isort --check-only src/ tests/  # or isort src/ tests/
- mypy src/

4) Try the CLI in dry runs (no network):
- excog clean --output-dir tmp_results --output-data tmp_processed
- excog impute --data-path tmp_processed/cleaned_nhanes.csv --n-imputations 1 --n-iterations 1

Keep heavy operations and downloads behind explicit markers when testing.
